Elm / Effects Redesign for toron + flywheel + beads

One Model, one Msg, tick → (Model, Vec<Effect>). Effects journaled before execution. Judgment (Jev/System-One) as a typed Effect, never a stringly prompt. This blueprint was built from live code reads across all three repos, the effect-oriented Rust + patterns references, and the TypeSafe System-One docs.

toron 5 crates flywheel src + doorbell-core/rt/cli beads br ADR-0019 · 0027 · 0028 · 0031 · 0032 ask_judgment seam already exists
Bottom line. Keep the four pure cores that already work (dispatch_core, boundary partition, receipts monotonic machine, beads verify/hold). Delete the five structural sins around them: clock-in-reducer, sync ActionRunner + block_on thread-hop, Recording-mode unjournaled execution, 7-stores-no-truth, and four wake caches. Promote Jev from a CLI child-process call into a first-class journaled Effect::Judge with Choice/Score/Noul packs. The rest of this page is the how, in waves.

2 · The law (one paragraph, then enforced by types)

Law: every decision core is one Model + one Msg union + tick(&Model,&Msg) → (Model, Vec<Effect>). No I/O across the tick boundary. Wall-clock, randomness, env, and network enter only as Msg payloads. Every Effect is journaled (prepare → claim → settle/fail/unknown) before execution, keyed by a stable derivation that excludes attempt number. Sensors are Msg producers. Sinks are Effect interpreters. Jev judgment is an Effect like any other: question pack + state in, typed answers + JudgmentEffect out, replayed by effect_key, never re-asked. Anything that breaks this fails closed at the type level, not in a code-review comment.

This is ADR-0031 (Elm cores) + ADR-0032 (honesty/journal) + ADR-0027 (one tick) + ADR-0019 (principles as lint, not prose) composed, with the effect-oriented skill supplying the Rust mechanics (Result/?, trait-injected Clock/Store/Rng, tower resilience outside-in, RAII cleanup, fakes in tests) and the TypeSafe skill supplying the judgment mechanics (Choice/Score/Noul, parallel speculative fan-out, confidence-gated routing, composite scoring).

3 · Target architecture

A · Kernel pattern (copy dispatch_core)

Each core gets: Model / Msg / Effect / tick / Guards / machine_config(), an import-fence test (no tokio/nostr/sqlx/env/time in the core file), a determinism test (same Msg log → byte-identical Effects), and BFS/DFS model-paths tests with invariants. Apply to: reservations, receipts, wake routing, loop phases, beads holds/close, cron catchup.

B · Effect pattern (copy boundary)

Each effectful leaf goes through an exhaustive partition(): EngineControl (pure) vs HostSink (journaled) vs Unsupported (fail-closed). Async EffectRunner only; delete sync ActionRunner and its block_on bridge. Delay returns a typed Unit, never Null. compat paths route through the same partition.

C · Judgment pattern (promote ask_judgment)

Jev becomes Effect::Judge{pack_id, effect_key, state}. Packs are versioned Choice/Score/Noul question sets (flywheel resolves pack_id; unknown pack = typed error). Offline transport = pure deterministic answers for tests. System-one = live model. Idempotent replay on effect_key. Confidence gates routing in code, never inside the question.

4 · Jev / System-One placement (the highest-leverage change)

Where judgment belongs

  • Routing triage (flywheel decide): Choice over primitives {steer, loop-work, wave-swarm, repair, beads-lifecycle, coalition, none} + Noul per risk flag (multi-lane? file-contention? bead-ready?). Replaces substring trigger fragility with calibrated probabilities + confidence-gated fallback to none.
  • Wake prioritization (doorbell brain): Score(urgency) + Score(actionability) + Noul(interrupt-worthy?) per inbox row. Composite score in code decides Inject vs Digest vs Queue. Ends the 7-gate sprawl with one GateDecision type.
  • Beads triage/next: Score(value) + Score(risk) + Noul(dispatchable?) feed PageRank/betweenness signals as composite features, not replacements. Labeled outcomes become classical ML features later (TypeSafe cookbook pattern).
  • Verify adjudication: Noul(does evidence satisfy VERIFY?) + citation-check Choice over the artifact, with low-confidence → human review. ce-evaluate stays advisory; the sink owns the verdict.
  • Guardrails: every LLM-bound prompt (stage payloads, spawn briefs) screened by one hazard-Noul + severity-Score request; threshold in code decides pass/review/block/route.

How to wire it (concrete)

  • Keep ask_judgment(effect_key, pack_id, state, transport, timeout) as the only Jev door. Add pack_version to the journal row; pack registry lives in flywheel (flywheel principles/judgment surfaces), resolved outside tick via Cmd::Reclassify-style effect.
  • Question packs are data: Pack{id, version, questions: [Choice|Score|Noul], state_schema}. State is named JSON fields (source text, identities, policies, facts). Question IDs are for code, full meaning inline.
  • Ask independent + speculative questions in one call (fan-out pattern). Second call only when an earlier answer selects new evidence/options.
  • Thresholds evaluated on your data with consequences in mind. Choice/Score confidence = distribution concentration, not permission to act. Noul 0.5 = genuinely uncertain, route to human.
  • Offline transport must be hermetic and seeded: scripted answers per pack for unit tests (fail-twice-then-succeed for retry tests, hang for timeout tests, storm for breaker tests).
  • Journal the typed answers + confidence + usage + fallback_flag + escalated (already in JudgmentEffectRecord — add pack_version + state_hash). Replay returns the row, never re-asks.

What NOT to do. No compat shims, no second buses, no silent-success stubs, no nested block_on, no new kinds/tools without an ADR, no threaded clock reads, no prompt text as control flow, no reruns of a settled judgment. Fail-closed mechanisms stay shut; a broken gate gets a loud BYPASS record, never a quiet workaround.

8 · Risks + open choices

Risks

  • Journal-everything latency — per-leaf prepare/claim/settle adds sqlite writes on wave-swarm fanout. Mitigate: single journal executor channel, batch claims, measure before/after.
  • Jev cost/quality — live judgment per route/wake/triage costs tokens and can misroute. Mitigate: offline-first packs, confidence thresholds tuned on your data, human escalation on Noul≈0.5, labeled outcomes → classical features.
  • Storage migration — events-table cutover risks archive/index skew. Mitigate: dual-write + rebuild-verify wave before switching readers; keep Git archive as rebuild source.
  • Scope creep — three repos at once. Mitigate: waves are per-core and independently shippable; wave 1 alone pays off.

Choices for you

  • Jev provider: keep ask_judgment offline-first with system-one opt-in per pack, or default live with offline fallback? Recommended: offline default, live per-pack flag.
  • Beads JSONL: keep the file as a human-readable projection, or move humans to br show --json + TUI? Recommended: keep projection, fix flush.
  • First core to purify: receipts (smallest, highest replay value) vs reservations (biggest pain). Recommended: receipts first, reservations second.
  • Wave-swarm default: keep planner+coder+reviewer 3-pane, or slim to coder+reviewer for small beads? Keep 3 for P≤2, 2 for P3+.
